# Sistema Patrimonial

Aplicação web leve para gerir imóveis, pagamentos mensais, gastos e documentos. Foi reconstruída a partir do flow do Node-RED, sem as integrações de MQTT e Discord.

## Tecnologias

- HTML, CSS e JavaScript puro — não exige Node.js, npm ou framework.
- Supabase Auth, REST API e Supabase Storage.

## Funcionalidades

- **Casas:** cadastrar, consultar e excluir imóveis, com endereço e renda mensal.
- **Pagamentos:** visualizar receitas por mês e marcar cada pagamento como recebido ou pendente. No mês corrente, um registro pendente é criado automaticamente para cada casa que ainda não o possua, exatamente como no flow original.
- **Gastos:** cadastrar despesas por casa, categoria e valor; marcar como pago e excluir.
- **Documentos:** enviar PDF, PNG ou JPEG de até 10 MB, abrir por uma URL temporária e excluir. Os arquivos vão para o bucket `documentos`.
- **Acesso:** criação de conta e login por e-mail/senha usando o Supabase Auth. A sessão fica salva no navegador até o usuário sair.

## Como executar

1. Crie um arquivo chamado `config.js` na raiz do projeto a partir de `config.example.js`.
2. Preencha a URL do Supabase e uma chave **anon/public** válida. A URL pode ser a raiz (`https://seu-projeto.supabase.co`) ou a URL REST antiga usada no flow (`https://seu-projeto.supabase.co/rest/v1/`); a aplicação aceita ambas.
3. No Supabase, em **Authentication > Providers**, habilite o provedor **Email**. Se a confirmação de e-mail estiver ativada, o usuário precisará confirmar a mensagem recebida antes de fazer login.
4. Sirva a pasta por um servidor HTTP local. Por exemplo, com a extensão Live Server do VS Code, ou:

   ```powershell
   python -m http.server 8080
   ```

5. Abra `http://localhost:8080` no navegador.

`config.js` está no `.gitignore`, portanto credenciais não serão incluídas em commits. Nunca use a chave `service_role` no navegador.

## Configuração do Supabase

O projeto usa as tabelas que já existiam no flow:

| Tabela | Campos utilizados |
|---|---|
| `casa` | `id`, `created_at`, `rua`, `numero`, `complemento`, `renda` |
| `pagamentos_casa` | `casa_id`, `pago`, `data` |
| `gastos_casa` | `id`, `casa_id`, `descricao`, `categoria`, `valor`, `pago`, `recorrente`, `data` |
| `documentos_casa` | `id`, `casa_id`, `nome_arquivo`, `tipo_arquivo`, `tamanho`, `caminho_arquivo`, `descricao`, `data_upload` |

Todas as tabelas também usam `user_id`, uma chave estrangeira para `auth.users(id)`. A migração de isolamento por usuário está em `supabase/migrations/20260916_vincular_dados_a_usuarios.sql`.

Também é necessário um bucket privado chamado `documentos`. Os arquivos são gravados no formato:

```text
casas/<id-da-casa>/<timestamp>_<nome-do-arquivo>
```

Se for necessário recriar o banco, este SQL cria uma base compatível:

```sql
create table public.casa (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  rua text not null,
  numero integer not null,
  complemento text,
  renda numeric not null check (renda >= 0)
);

create table public.pagamentos_casa (
  casa_id bigint not null references public.casa(id) on delete cascade,
  pago boolean not null default false,
  data date not null,
  primary key (casa_id, data)
);

create table public.gastos_casa (
  id bigint generated by default as identity primary key,
  casa_id bigint not null references public.casa(id) on delete cascade,
  descricao text not null,
  categoria text not null,
  valor numeric not null check (valor > 0),
  pago boolean not null default false,
  recorrente boolean not null default false,
  data date not null
);

create table public.documentos_casa (
  id bigint generated by default as identity primary key,
  casa_id bigint not null references public.casa(id) on delete cascade,
  nome_arquivo text not null,
  tipo_arquivo text not null,
  tamanho bigint not null,
  caminho_arquivo text not null unique,
  descricao text,
  data_upload timestamptz not null default now()
);
```

### Políticas de acesso

Como esta é uma aplicação de navegador, as políticas RLS do Supabase precisam permitir operações somente ao usuário autenticado que é proprietário do registro. Execute a migração `supabase/migrations/20260916_vincular_dados_a_usuarios.sql` no SQL Editor: ela adiciona `user_id`, associa os dados antigos ao proprietário informado, ativa RLS e aplica políticas baseadas em `auth.uid()` nas quatro tabelas.

O bucket `documentos` deve permanecer privado. Configure suas políticas de Storage para que usuários autenticados só possam acessar os próprios arquivos; a tabela `documentos_casa` já ficará isolada pela migração.

Não copie para este repositório a chave que estava no export do Node-RED. Revogue/rotacione qualquer chave que tenha sido compartilhada e use uma nova chave anon/public no `config.js`.

## Observações sobre o flow original

- MQTT e Discord foram propositalmente removidos.
- A aba duplicada de documentos e a versão desativada do flow não foram trazidas.
- A aplicação não cria pagamentos automaticamente para meses anteriores, preservando a regra original.
